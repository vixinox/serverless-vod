# 1 绪论

随着移动互联网、宽带网络和智能终端的快速普及，在线视频已成为互联网内容消费的重要形态之一。无论是长视频平台、短视频平台，还是在线教育、企业培训和活动直播回看系统，视频点播都已经成为支撑数字内容传播的基础能力。与图文类业务相比，视频业务在数据量、处理链路和分发方式上具有更高复杂度，尤其是在上传、转码、存储、分发和播放等环节，对系统架构的弹性、稳定性和可维护性提出了更高要求。因此，围绕视频点播平台的架构设计与实现开展研究，具有较强的现实意义和工程价值。

本课题面向中小规模视频业务场景，结合现代全栈 Web 技术与 AWS Serverless 架构，设计并实现一个具备上传、转码、播放、互动、管理和统计能力的视频点播平台。论文不仅关注系统功能实现，还重点讨论如何利用对象存储、函数计算、工作流编排和事件驱动机制提升系统的资源利用率与开发效率，从而为同类业务提供一种可复用的技术实践方案。

## 1.1 课题背景

近年来，在线视频业务持续增长，用户对视频内容的访问场景也日益多样化，视频平台从单纯的内容展示逐渐转向“内容生产、处理、分发、互动、分析”一体化发展。与此相对应，平台系统不再只需要支持前端页面展示，还必须具备视频上传、异步转码、封面抽取、流媒体播放、评论互动、收藏订阅以及运营统计等完整能力。尤其是在用户自主上传视频的业务场景中，视频源文件大小不一、清晰度和编码格式各异，给平台在媒体处理和资源调度方面带来了显著挑战。

传统视频平台通常采用自建服务器或云主机集群来承载媒体处理任务，通过常驻式转码服务、消息中间件和分发组件完成上传后的处理流程。这类方案在业务规模稳定、资源投入充足的情况下具有一定优势，但其短板也较为明显：一方面，视频处理任务具有波峰波谷明显、资源占用高的特点，固定资源池容易出现高峰期不足、低峰期闲置的问题；另一方面，转码服务、文件存储、任务调度和状态管理等模块往往需要分别部署和维护，系统整体复杂度较高，难以快速响应新业务试错需求。

在云计算快速发展的背景下，以对象存储、函数计算和工作流编排为代表的 Serverless 技术逐渐成熟，为视频平台提供了新的架构思路。相较于传统架构，Serverless 架构能够按需启动计算资源，通过事件驱动方式组织媒体处理流程，将大文件上传、异步转码和状态回写等步骤解耦，降低基础设施维护成本，并提高系统的扩展能力。对于中小型视频平台、教学实验项目或新业务验证场景而言，这种方式具有较高的适用性。

基于上述背景，本文选择以 AWS Serverless 架构为核心，结合 Next.js 16、React 19、PostgreSQL、Prisma、FFmpeg、HLS 和 Better Auth 等技术，设计并实现一套视频点播平台，并围绕其架构合理性与工程可行性展开研究。

## 1.2 研究目的与意义

本课题的研究目的在于设计并实现一个基于 AWS Serverless 架构的视频点播平台，构建从视频上传、媒体处理、内容发布到在线播放和行为采集的完整业务闭环。在实现层面，系统需要支持首页浏览、搜索、频道展示、视频播放、评论互动、收藏与播放列表、内容管理以及统计分析等核心功能；在架构层面，则需要重点验证 Serverless 技术在视频点播场景中的适配性，分析其在弹性扩展、成本控制、开发效率和运行维护方面的优势。

从理论意义看，视频点播平台是典型的“业务逻辑与媒体处理链路并存”的应用系统，既包含前端交互、数据建模和权限控制等常见 Web 系统问题，也涉及大文件上传、异步转码、流媒体封装和状态同步等复杂工程问题。本文将现代全栈开发技术与 Serverless 媒体处理流程结合起来，对视频平台架构进行系统化分析与实现，有助于为相关领域的课程设计、毕业设计和工程实践提供参考。

从实践意义看，中小团队或新业务在建设视频平台时，往往更关注开发效率、部署成本和后续扩展能力，而非一开始就投入完整的自建媒体基础设施。本文所实现的方案通过对象存储承载视频文件，通过 Step Functions 编排 Lambda 处理转码任务，并结合 EventBridge 进行阶段反馈，再以 PostgreSQL 和 Prisma 管理结构化业务数据，在保证功能完整性的同时降低了系统耦合度。研究结果可为类似业务提供一种“低门槛、可扩展、可快速验证”的视频平台建设思路。

此外，本项目在工程实现中还引入了 LocalStack 作为本地云服务仿真环境，使开发阶段能够在较低成本下验证对象存储、工作流和事件总线等核心链路。这不仅提升了开发调试效率，也增强了研究结论的可操作性和现实参考价值。

## 1.3 国内外研究现状

当前国内外视频点播平台的实现方案大致可归纳为三类。

第一类是以自建服务器或云主机集群为核心的传统方案。这类方案通常以 Nginx、FFmpeg、数据库和缓存系统为基础，通过应用服务接收上传请求，再由转码服务将视频转换为可分发格式，最终结合对象存储或 CDN 提供播放访问。该方案的优点是架构可控性强、组件选择自由度高，适用于对底层基础设施掌控要求较高的场景；但缺点是前期部署复杂、资源预留成本高，且需要长期维护服务器、任务调度和扩缩容策略。

第二类是基于容器和微服务的云原生方案。此类方案通常引入 Docker、Kubernetes、消息队列、网关和监控系统，将上传、转码、用户管理、推荐和统计等能力拆分为多个服务，并通过编排平台实现自动伸缩。这类方案在中大型业务中应用广泛，能够兼顾服务隔离与扩展能力，但其系统治理和运维门槛较高，对研发团队的工程能力和基础设施投入提出了较高要求。

第三类是基于公有云托管服务和 Serverless 架构的方案。国外云平台较早提供了对象存储、函数计算、媒体服务、工作流编排和内容分发能力，使开发者可以基于云原生服务快速构建视频处理流水线。近年来，随着事件驱动设计理念的发展，越来越多研究和工程实践开始关注如何通过函数计算与工作流编排替代部分常驻式媒体处理服务，以适应不稳定流量和快速试错需求。国内在这一方向上的实践也逐步增多，但不少研究仍偏重单一技术点验证，如转码效率、流媒体播放或云服务组合，而对“前端交互、用户体系、业务数据闭环、可观测性与运维纠偏”进行一体化设计的工作相对较少。

从现有研究成果来看，视频点播系统在上传、转码和播放等基础能力上已经形成较为成熟的实现路径，但仍存在若干不足。其一，不少方案更强调媒体处理本身，对平台级业务能力关注不足，例如账号体系、频道管理、评论互动和创作者工作台等功能往往没有被纳入统一架构。其二，部分研究使用的技术链较为分散，前端、后端、认证、媒体处理和统计模块之间耦合松散，导致实现结果难以形成完整的工程闭环。其三，关于 Serverless 架构在视频点播场景中的应用研究虽然逐步增多，但真正结合现代全栈框架、关系型数据库与事件驱动媒体流水线进行系统实现和可行性分析的案例仍有进一步深入空间。

因此，本文的研究重点并不在于提出全新的媒体处理算法，而是在现有研究和成熟技术基础上，结合 Next.js 16、React 19、PostgreSQL、Prisma、Better Auth 以及 AWS Serverless 相关服务，构建一套端到端的视频点播平台，实现业务功能与媒体流水线的统一设计，并从工程视角验证该方案在中小规模视频业务中的应用价值。

## 1.4 研究内容

围绕“基于 AWS Serverless 架构的视频点播平台设计与实现”这一主题，本文的主要研究内容包括以下几个方面。

首先，完成系统需求分析与总体架构设计。结合视频平台的典型业务场景，对游客、注册用户和创作者等角色进行划分，明确首页浏览、视频播放、评论互动、频道展示、收藏与播放列表、视频上传、内容管理和统计分析等功能需求，并在此基础上设计系统整体架构、模块划分与数据流转关系。

其次，完成视频点播平台的核心功能实现。前端基于 Next.js 16 与 React 19 构建，负责首页推荐、搜索、视频详情页、频道页、登录注册页和创作者工作室等界面；后端依托 Next.js 的服务端能力、Route Handler 和 Server Action 组织业务逻辑，结合 PostgreSQL 与 Prisma 完成用户、频道、视频、评论、收藏、播放列表和统计数据的持久化管理；认证部分使用 Better Auth 实现邮箱密码登录与第三方登录扩展。

再次，完成基于 AWS Serverless 思路的媒体处理流水线设计与实现。系统通过对象存储接收视频文件上传，并使用预签名 URL 降低应用服务器传输压力；上传完成后，由 Step Functions 触发并编排 Lambda 执行元数据提取、FFmpeg 转码、HLS 切片、封面抽取和结果回写等步骤；同时结合 EventBridge 和内部接口对流水线阶段进行反馈，使前端能够获取更细粒度的任务状态信息。

最后，围绕系统运行效果开展可行性与实现效果分析。本文将结合项目实际完成情况，对系统功能完整性、架构合理性、运行维护便利性和扩展空间进行总结，并分析 Serverless 架构在视频点播场景中的适用价值，为同类项目的技术选型与工程实现提供参考。

## 1.5 论文组织结构

为清晰展示本课题的研究过程与实现结果，全文共分为七章，具体安排如下。

第一章为绪论，主要介绍课题背景、研究目的与意义、国内外研究现状、研究内容以及论文整体结构。

第二章为相关技术与可行性分析，重点阐述 Serverless 架构、Next.js 16 与 React 19、PostgreSQL 与 Prisma、AWS 相关服务、FFmpeg 与 HLS 技术、Better Auth 认证机制，并从技术、经济和运行维护三个方面分析系统的可行性。

第三章为需求分析，围绕系统角色、功能需求、非功能需求、业务用例和领域模型展开分析，为后续系统设计提供依据。

第四章为系统设计，主要从总体架构、业务流程、功能模块、数据库、接口以及部署与本地仿真环境等方面介绍系统设计方案。

第五章为系统实现，详细说明用户认证、视频浏览与播放、评论互动、收藏与播放列表、视频上传与媒体处理流水线、创作者工作室以及统计分析等模块的具体实现过程。

第六章为系统测试，介绍测试环境、测试计划、功能测试以及性能与可靠性测试内容，并对系统测试结果进行总结。

第七章为总结与展望，总结本文的主要研究成果、系统实现效果以及存在的不足，并展望后续可进一步扩展和优化的方向。
