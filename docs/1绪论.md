# 1 绪论

随着移动互联网、宽带网络和智能终端的普及，在线视频已成为互联网内容消费的重要形态。无论是长视频平台、短视频平台，还是在线教育、企业培训和活动回看系统，视频点播都已经成为数字内容传播的基础能力。与图文类业务相比，视频业务在数据规模、处理链路和分发方式上更为复杂，尤其是在上传、转码、存储、分发和播放等环节，对系统架构的弹性、稳定性和可维护性提出了更高要求。因此，围绕视频点播平台的设计与实现展开研究，具有较强的现实意义和工程价值。

本课题面向中小规模视频业务场景，结合现代 Web 技术与 AWS Serverless 架构，设计并实现一个具备上传、转码、播放、互动、管理和统计能力的视频点播平台。论文在关注系统功能实现的同时，也讨论如何借助对象存储、函数计算、工作流编排和事件驱动机制提升开发效率与资源利用率，从而为同类业务提供一种可复用的实践思路。

## 1.1 课题背景

近年来，在线视频业务持续增长，用户对视频内容的访问场景也日益多样化，视频平台从单纯的内容展示逐渐转向“内容生产、处理、分发、互动、分析”一体化发展。与此相对应，平台系统不再只需要支持前端页面展示，还必须具备视频上传、异步转码、封面抽取、流媒体播放、评论互动、收藏订阅以及运营统计等完整能力。尤其是在用户自主上传视频的业务场景中，视频源文件大小不一、清晰度和编码格式各异，给平台在媒体处理和资源调度方面带来了显著挑战。

传统视频平台通常采用自建服务器或云主机集群来承载媒体处理任务，通过常驻式转码服务、消息中间件和分发组件完成上传后的处理流程。这类方案在业务规模稳定、资源投入充足的情况下具有一定优势，但其短板也较为明显：一方面，视频处理任务具有波峰波谷明显、资源占用高的特点，固定资源池容易出现高峰期不足、低峰期闲置的问题；另一方面，转码服务、文件存储、任务调度和状态管理等模块往往需要分别部署和维护，系统整体复杂度较高，难以快速响应新业务试错需求。

在云计算快速发展的背景下，以对象存储、函数计算和工作流编排为代表的 Serverless 技术逐渐成熟，为视频平台提供了新的架构思路。相较于传统架构，Serverless 架构能够按需启动计算资源，通过事件驱动方式组织媒体处理流程，将大文件上传、异步转码和状态回写等步骤解耦，降低基础设施维护成本，并提高系统的扩展能力。对于中小型视频平台、教学实验项目或新业务验证场景而言，这种方式具有较高的适用性。

基于上述背景，本文选择以 AWS Serverless 架构为核心，结合 Next.js 16、React 19、PostgreSQL、Prisma、FFmpeg、HLS 和 Better Auth 等技术，设计并实现一套视频点播平台，并围绕其架构合理性与工程可行性展开研究。

## 1.2 研究目的与意义

本课题的研究目的在于设计并实现一个基于 AWS Serverless 架构的视频点播平台，构建从视频上传、媒体处理、内容发布到在线播放和行为采集的业务闭环。在功能层面，系统需要支持首页浏览、搜索、频道展示、视频播放、评论互动、收藏与播放列表、内容管理以及统计分析等核心能力；在架构层面，则重点验证 Serverless 技术在视频点播场景中的适用性。

从理论意义看，视频点播平台兼具 Web 应用与媒体处理系统的双重特征，既涉及前端交互、数据建模和权限控制，也涉及大文件上传、异步转码和流媒体封装等问题。将现代 Web 开发技术与 Serverless 媒体处理流程结合起来，有助于为相关课题研究和工程实践提供参考。

从实践意义看，中小团队或新业务在建设视频平台时，更关注开发效率、部署成本和后续扩展能力。本文通过对象存储、工作流编排、云函数和关系型数据库构建整体方案，并引入 LocalStack 进行本地仿真验证，为类似业务提供了一种较低门槛、便于扩展的视频平台建设思路。

## 1.3 国内外研究现状

当前国内外视频点播平台的实现方案大致可归纳为三类。

第一类是以自建服务器或云主机集群为核心的传统方案。这类方案通常以 Nginx、FFmpeg、数据库和缓存系统为基础，通过应用服务接收上传请求，再由转码服务将视频转换为可分发格式，最终结合对象存储或 CDN 提供播放访问。该方案的优点是架构可控性强、组件选择自由度高，适用于对底层基础设施掌控要求较高的场景；但缺点是前期部署复杂、资源预留成本高，且需要长期维护服务器、任务调度和扩缩容策略。

第二类是基于容器和微服务的云原生方案。此类方案通常引入 Docker、Kubernetes、消息队列、网关和监控系统，将上传、转码、用户管理、推荐和统计等能力拆分为多个服务，并通过编排平台实现自动伸缩。这类方案在中大型业务中应用广泛，能够兼顾服务隔离与扩展能力，但其系统治理和运维门槛较高，对研发团队的工程能力和基础设施投入提出了较高要求。

第三类是基于公有云托管服务和 Serverless 架构的方案。国外云平台较早提供了对象存储、函数计算、媒体服务、工作流编排和内容分发能力，使开发者可以基于云原生服务快速构建视频处理流水线。近年来，随着事件驱动设计理念的发展，越来越多研究和工程实践开始关注如何通过函数计算与工作流编排替代部分常驻式媒体处理服务，以适应不稳定流量和快速试错需求。国内在这一方向上的实践也逐步增多，但不少研究仍偏重单一技术点验证，如转码效率、流媒体播放或云服务组合，而对“前端交互、用户体系、业务数据闭环、可观测性与运维纠偏”进行一体化设计的工作相对较少。

从现有研究成果来看，视频点播系统在上传、转码和播放等基础能力上已经形成较为成熟的实现路径，但仍存在若干不足。其一，不少方案更强调媒体处理本身，对平台级业务能力关注不足，例如账号体系、频道管理、评论互动和创作者工作台等功能往往没有被纳入统一架构。其二，部分研究使用的技术链较为分散，前端、后端、认证、媒体处理和统计模块之间耦合松散，导致实现结果难以形成完整的工程闭环。其三，关于 Serverless 架构在视频点播场景中的应用研究虽然逐步增多，但真正结合现代全栈框架、关系型数据库与事件驱动媒体流水线进行系统实现和可行性分析的案例仍有进一步深入空间。

因此，本文的研究重点并不在于提出全新的媒体处理算法，而是在现有研究和成熟技术基础上，结合 Next.js 16、React 19、PostgreSQL、Prisma、Better Auth 以及 AWS Serverless 相关服务，构建一套端到端的视频点播平台，实现业务功能与媒体流水线的统一设计，并从工程视角验证该方案在中小规模视频业务中的应用价值。

## 1.4 研究内容

围绕“基于 AWS Serverless 架构的视频点播平台设计与实现”这一主题，本文从需求建模、系统实现与架构验证三个层面展开研究，并尝试将业务功能与媒体处理流程纳入统一工程框架。

在需求与架构层面，本文结合视频平台的典型使用场景，对游客、注册用户和创作者等角色的行为路径进行梳理，归纳平台在内容浏览、在线播放、社交互动、视频上传、后台管理与数据统计等方面的核心诉求，并据此明确系统边界、模块关系及数据流转逻辑。

在功能实现层面，系统围绕内容浏览、视频播放、评论互动、频道展示、播放列表、创作者工作台与统计分析等核心模块展开，形成“前台内容消费 + 后台内容治理”的协同结构。通过统一的数据模型与接口约束，各模块在保持职责清晰的同时实现稳定协作，从而提升系统整体的一致性与可维护性。

在媒体处理与方案验证层面，本文重点设计并实现了基于 AWS Serverless 思路的视频处理流水线，利用对象存储事件、工作流编排与云函数机制，将上传后的转码、封面抽取与状态回写组织为可追踪的异步流程。同时结合 LocalStack 进行本地仿真验证，对该方案在中小规模视频业务中的工程可行性与应用价值进行分析。

## 1.5 论文组织结构

为清晰呈现本课题从问题提出到系统落地的完整过程，全文共分七章，各章内容由理论分析逐步过渡到工程实现与效果验证。

第一章为绪论，主要阐述研究背景与课题意义，梳理国内外相关研究现状，明确本文的研究范围、研究内容与整体结构。第二章围绕系统建设所依赖的关键技术与可行性展开讨论，涵盖 Serverless 架构、Next.js 16 与 React 19、PostgreSQL 与 Prisma、AWS 相关服务、FFmpeg 与 HLS 以及 Better Auth，并从技术、经济与运维角度评估方案可行性。

第三章聚焦需求分析，从系统角色、功能需求、非功能需求、业务用例与领域模型等维度提炼设计依据。第四章在此基础上给出系统设计方案，说明总体架构、业务流程、模块划分、数据库结构、接口设计及本地仿真部署思路。第五章进一步展示系统实现过程，重点说明认证体系、视频浏览与播放、评论互动、收藏与播放列表、视频上传与媒体处理流水线、创作者工作室及统计分析等模块的实现细节。

第六章对系统测试进行说明，包括测试环境、测试计划、功能验证及性能与可靠性评估，并据此分析系统运行效果。第七章对全文工作进行总结，归纳研究成果与不足，并提出后续可进一步优化与扩展的方向。
