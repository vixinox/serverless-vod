一、研究的现状及其意义
当前视频点播平台的实现路径主要分为三类：一是以 Nginx/FFmpeg 为核心的自建服务器或云主机集群，配合对象存储与 CDN 完成分发；二是以 Kubernetes/容器为基础的微服务架构，通过自动伸缩承载波峰流量；三是以 AWS MediaConvert、S3、CloudFront 等托管媒体服务为主的云上方案，并逐步引入事件驱动与函数计算实现弹性处理。国内外亦有成熟的商业与开源产品覆盖上传、转码、播放与数据分析，但其典型使用场景多面向长期稳定业务或大规模平台，体系完整但建设与运维成本较高，且在“短周期验证、流量高度不确定”的新业务试错阶段，往往存在交付慢、资源预留多、链路改动成本高等问题。
既有方案的优势在于能力成熟、生态完善，能够在高并发下提供稳定的转码与分发，但其不足也较突出：自建与容器化方案需要预置计算资源、镜像与伸缩策略，扩缩容存在启动与调参成本，且前后端联动、数据模型、可观测性与权限体系常被拆散实现，导致研发效率与迭代速度受限；托管媒体服务虽然降低了媒体处理门槛，但若缺少与现代全栈工程化体系的整合，仍难以在权限、业务数据闭环、交互体验与运营指标采集上形成可复用的完整解决方案。本项目与过往研究的差异不在于单纯强调 Serverless 本身，而是在现代全栈技术链（TypeScript、播放端工程化、PostgreSQL/Prisma、OAuth 等）与事件驱动的云原生媒体流水线之间建立端到端的一体化设计与实现，并以性能与成本为可量化目标进行验证与优化。
本课题的意义在于面向中小团队短期活动与新业务冷启动等细分场景，提出一套“快速交付—弹性承载—数据闭环”的工程实践范式：通过将上传、转码、分发与业务数据管理解耦并自动化编排，在保证播放体验与可用性的同时降低运维复杂度与试错成本；通过统一的全栈架构把用户体系、内容管理与行为数据采集纳入同一技术栈，缩短从产品设想到上线验证的周期；并在真实压测与数据分析基础上总结性能瓶颈与费用结构，为类似业务提供可复用的架构选型依据与优化方法。








二、研究目标、研究内容和拟解决的关键问题
本项目的研究目标是开发一个基于 AWS Serverless 架构的高效弹性视频点播平台，旨在为新兴视频业务提供一个低成本、快速部署且高扩展性的平台。Serverless 的引入将使平台在高并发、低流量的场景下实现零成本运维与快速扩展。通过将视频上传、转码、分发、数据分析等功能解耦，并依托 AWS 的云原生服务，平台不仅能快速响应流量波动，还能提供极致的用户体验和运营数据支持。本项目的创新之处在于通过全栈技术链与 Serverless 的结合，形成了一种全新的、以事件驱动与自动化为核心的高效视频处理架构，适合面向初创团队与中小企业的新业务场景，尤其是在视频短期验证和试错阶段。
研究内容方面，前台部分将实现一个全面的视频播放界面，包括频道管理、视频收藏、播放列表、评论区等基本功能。通过 HLS（HTTP Live Streaming）流媒体技术与 hls.js 库的结合，提供自适应码率、无缝切换的视频播放体验，确保在不同网络环境下的高质量播放。后台部分则主要实现视频管理与数据分析功能，能够处理视频上传、转码、删除与更新等操作，并提供视频观看时长、码率切换频率、用户互动等数据的收集与可视化展示，为运营决策提供支持。研究过程中将重点研究如何结合 AWS 的服务（如 Lambda、SQS、Step Functions）高效实现视频转码流程、消息队列设计与流量控制，并确保平台在高并发场景下的高可用性与稳定性。
拟解决的关键问题主要集中在 AWS 上的消息队列设计、转码流程与错误处理机制。首先，如何设计高效的 SQS 队列与事件触发机制，确保视频上传、转码与分发过程中的任务能够高效排队与并行处理；其次，如何通过 AWS Step Functions 设计一个容错能力强、可恢复的转码流水线，在出现错误时能够自动重试，并精准记录每一步骤的状态与日志；再者，如何管理数据存储与分发，确保转码后的视频文件能够高效地存储于 S3，并通过 CloudFront 实现全球低延迟的内容分发。此外，前端 HLS 播放界面的高性能设计与优化也将是一个关键点，需确保视频播放界面能够适应不同设备与网络环境，实现流畅、稳定的用户体验。


三、研究的基本思路和方法、技术路线、实验方案及可行性分析
研究的基本思路与方法是以“现代全栈工程化 + Serverless 事件驱动媒体链路”为主线，先完成面向用户的视频点播与互动闭环，再实现面向运营端的视频管理与数据分析闭环，并在此基础上对高并发下的处理能力、稳定性与成本进行验证。系统以“上传—排队—转码—入库—分发—播放—行为采集”为核心流程：用户通过前台上传视频并获取可播放地址，后台以消息队列和工作流编排驱动转码任务，转码产物进入对象存储并通过 CDN 分发，播放端基于 HLS 进行自适应播放，同时持续采集观看与互动数据写入数据库，最终在管理端进行可视化展示与对比分析，从而形成可度量的性能与成本优化依据。
技术路线方面，前端采用React + TypeScript 完成页面渲染、频道/播放列表/评论等交互功能，并使用 hls.js 实现 HLS 播放器与码率自适应；认证与用户体系基于 NextAuth 与 Prisma Adapter 完成 OAuth/邮箱登录等能力。数据层以 PostgreSQL 存储用户、视频元数据与行为数据，Prisma 负责模型与访问。云端媒体链路以 S3 作为上传与转码产物存储，CloudFront 负责分发；转码与任务编排由 Step Functions 组织，队列采用 SQS 实现削峰填谷与重试，计算由 Lambda 执行关键业务逻辑与状态回写，并通过 CloudWatch 记录日志与指标，支撑后续压测与成本分析。
实验方案以可复现的开发与验证环境为主：本地开发使用 Bun/Node 运行 React 项目，依赖管理按项目 `package.json` 配置（React.js、hls.js、NextAuth、Prisma、PostgreSQL 等）；数据库可采用本地或云端 PostgreSQL 实例；AWS 侧准备 S3、CloudFront、SQS、Step Functions、Lambda 与监控告警配置，并通过压测工具模拟上传与播放并发，观察队列堆积、转码耗时、端到端延迟与费用变化，形成不同策略下的对比数据。可行性方面，关键组件均为成熟技术与标准服务，且本人具备前端、数据库与 AWS 架构经验，技术可行；系统交互形态与 YouTube/Studio 类似，用户学习成本低，操作可行；开发上可按“基础播放与上传→转码链路→互动与管理端→数据分析与压测优化”的顺序迭代，工作量可拆分并在毕设周期内完成。
