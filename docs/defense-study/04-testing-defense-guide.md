# 第6章测试答辩专项手册

## 你必须讲清楚的四件事

1. 为什么这样测。
2. 指标分别代表什么。
3. 结果说明了什么，不说明什么。
4. 下一步怎么优化。

## 指标解释模板

- 吞吐量（QPS）：单位时间可处理请求数，越高越好。
- 平均响应时间：总体体验的均值，不代表最差体验。
- P99响应时间：99% 请求都快于该值，反映尾延迟风险。
- 错误率：失败请求占比，0 并不等于系统已最优。

## 为什么选 50/100/200 并发

标准答法：

这组参数采用渐进加压策略，目的是观察系统在低中高压力下的稳定性趋势，而不是一次性压到极限。通过固定 Ramp-Up 与持续时间，保证三组结果可横向对比。

## 结果解读模板（对应你论文数据）

- 并发从 50 增到 200，吞吐量持续上升：说明系统仍可扩展。
- 平均RT与P99明显上升：说明排队和资源竞争开始出现。
- 错误率为0：说明系统可用，但不代表无优化空间。

## 有效性边界（必须主动说）

1. 测试环境是本地仿真，不等同真实云环境。
2. 重点压的是读取接口，不代表全链路写入场景。
3. 时长和并发档位有限，结论是“当前环境下有效”。

## 优化方向（可执行）

1. 数据库层：补热点查询索引，缩短慢查询。
2. 接口层：加缓存和分页策略优化，减少重复读取。
3. 应用层：降低不必要序列化和跨层调用。
4. 基础设施层：真实云环境复测并调优连接池。

## 高风险问题答法

### 问：为什么 P99 上升明显还说系统可用？

答：可用性与性能是两个维度。错误率为0说明请求能完成；P99上升说明高并发下尾延迟变差，需要优化，但不等于系统不可用。

### 问：为什么不做更高并发？

答：本阶段目标是验证架构可行性与趋势，不是做生产容量上限测定。后续会在真实云环境继续扩展并发与时长。

### 问：你的结论是否可直接推广到生产？

答：不能直接外推。结论限定在当前实验环境和当前接口场景，生产前需结合真实网络、真实流量模型和真实云资源复测。
