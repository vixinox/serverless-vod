# 毕设论文修改任务清单

## 第一阶段：先把结构调对

- 按学院最新模板检查封面、题目页、摘要页和年份信息，确保中英文标题、摘要、关键词齐全且格式一致。
- 先不要纠结目录排版，等正文结构改完、标题层级稳定后再统一更新目录。
- 把“系统设计”和“系统实现”的边界分开：设计章保留总体设计、数据库设计、接口设计；各功能的详细说明、时序图、页面截图放到系统实现章。

## 第二阶段：按会议意见补核心内容

- 重做第 3 章需求分析中的用例部分：按模块补标准用例图，并给主要用例配用例描述。
- 精简第 4 章功能模块设计，避免写成实现说明。
- 展开数据库设计：核心数据表分别列出字段名、数据类型、主键/外键、是否可空和字段含义。
- 接口设计保留表格形式，优先把主要接口补完整。

## 第三阶段：补系统实现章节

- 单独补写“系统实现”章节，按模块展开。
- 每个模块统一采用“文字说明 + 时序图/流程图 + 页面截图”的写法。
- 截图和说明以你最终 `docx` 内容为准，不强依赖当前 Markdown。

## 第四阶段：统一润色

- 压缩开题报告和正文里偏长、偏空泛的可行性表述。
- 通读一遍，把明显像 AI 生成的表达改得更自然一些，减少套话和重复句式。
- 最后统一检查标题编号、图表编号、表述风格和目录生成结果。

## 备注

- 这份清单按会议要求做了压缩，只保留当前最重要的修改项。
- 由于你的 `docx` 已经有手动调整，实际修改时以 `docx` 为主，Markdown 只作为参考材料。
