> 目标：这是一份唯一主入口手册。你只练这份文档，背到 80%-90% 即可覆盖大多数现场追问。

## 使用方式（先看）

- 本手册不是按论文目录背诵，而是按“老师会怎么疑问”来组织。
- 你所有回答都按固定框架：`先翻译概念 -> 再落到本项目 -> 给出代码/论文证据 -> 主动交代边界`。
- 每个核心主题都提供三层口径：`20秒`、`60秒`、`120秒`，用于应对被打断、追问加深、完整展开三种节奏。

## 老师心智模型声明（必须牢记）

- 默认评委熟悉“传统 Web/数据库系统”，但不熟悉 `Serverless`、`Node`、`Step Functions`。
- 所有陌生术语首次出现必须先白话，再说技术名词。
- 你不是在秀技术词，而是在“给老师上小课 + 证明你真的做出来了”。

## 训练与现场节奏切换

- 每日最小闭环：`20题快问快答 + 8分钟陈述 + 错题回炉`。
- 现场若被打断：先 20 秒回答问题，再用 1 句话接回主线。
- 现场若时间不足：优先保留“媒体处理链路 + 测试边界 + 不足与展望”三块。

## 第二部分：8-10分钟陈述主线（疑问路径版）

### 0:00-0:40 开场：问题定义

- 中小视频平台难点不是页面，而是大文件上传、异步转码、状态一致性与可恢复。
- 本项目目标：用低运维成本完成上传、处理、播放、互动、统计闭环。

### 0:40-1:40 为什么不是传统集群

- 传统常驻转码集群在流量波动下容易“低峰浪费、高峰吃紧”。
- 选 `AWS Serverless` 思路：按任务触发计算，把流程拆分成可观测阶段。

### 1:40-3:40 核心链路（必须清楚）

- 前端拿预签名地址直传 `S3` 原始桶。
- 后端创建 `UploadSession + TranscodeJob` 并启动 `Step Functions`。
- 状态机编排 `Lambda` 执行提取元数据、转码、HLS 切片、封面生成、回写状态。
- 播放页读取 `VideoAsset`，通过 HLS 主清单播放。

### 3:40-5:20 一致性与异常恢复

- 成功路径：`UPLOADING -> PROCESSING -> READY`。
- 失败路径：任一关键阶段异常进入 `FAILED` 并统一落库。
- 兜底机制：`reconcile-stale` 防止任务长期卡死。

### 5:20-6:50 功能闭环与实现

- 业务侧：认证、浏览、搜索、播放、评论、收藏、播放列表、创作者工作室、统计图表。
- 工程侧：Route Handler 薄层、`lib/server/*` 业务层、`prisma` 数据模型、`lib/localstack.ts` 基础设施封装。

### 6:50-8:20 测试与结论边界

- 功能测试 + 异常恢复测试 + 并发压测（50/100/200）。
- 结论是“当前实验环境可行且稳定”，不是“已达大型生产平台水平”。

### 8:20-9:30 不足与展望

- 不足：真实云环境与生产级验证未完全覆盖。
- 展望：真实 AWS/CDN 复测、多码率、内容审核、监控告警、写链路压测。

## 第三部分：核心技术双通道讲解（三层口径）

> 使用规则：被打断先给 20 秒；老师继续问给 60 秒；明确让你展开再给 120 秒。

### 1) Serverless（无服务器架构）

- **20秒**：不是没有服务器，而是把服务器运维、扩缩容交给云平台，你专注业务流程。
- **60秒**：本项目把同步请求留给 Next.js，把耗时媒体任务交给 Step Functions + Lambda，减少常驻转码服务运维负担。
- **120秒**：在上传后处理场景里，任务波动明显。用状态机编排函数可把提取、转码、切片、回写拆为阶段，失败可控且可观测。边界是冷启动、配额和真实云成本仍需专项验证。

### 2) 预签名上传 URL（Presigned URL）

- **20秒**：让客户端直接把大文件上传对象存储，后端只做授权，不做文件中转。
- **60秒**：后端生成一次性、短时有效的 PUT 地址；客户端直传 `vod-raw/{shortCode}/source.mp4`；上传成功后再创建转码任务。
- **120秒**：这把“文件传输”和“业务任务开始”拆成两个节点，便于失败重试与状态治理。安全上通过过期时间、对象键约束和登录校验控制范围。

### 3) Step Functions（工作流编排）

- **20秒**：它像“有状态任务调度器”，负责步骤顺序、重试和失败分支。
- **60秒**：本项目把 `ExtractMetadata -> Transcode -> Finalize` 编排进状态机，失败走 `MarkFailed`，避免单函数大杂烩。
- **120秒**：对多阶段异步流程，消息队列只解决“谁来消费”，状态机还解决“按什么顺序、失败后怎么办”。这在媒体处理链路上更贴合。

### 4) EventBridge（事件总线）

- **20秒**：它负责广播“处理到哪一步了”，方便后续扩展通知、告警、审计。
- **60秒**：当前前端主要读数据库轮询状态，EventBridge 作为事件出口保留扩展能力，不耦合核心转码逻辑。
- **120秒**：媒体处理阶段既要落库保当前功能，也要发事件保后续能力。这个“双轨”设计让系统现在能用、以后能扩。

### 5) HLS（流媒体切片）

- **20秒**：把长视频拆成清单和小片段，播放器按清单边下边播。
- **60秒**：转码后输出 `master.m3u8 + seg_*.ts`，播放页只需读取主清单即可连续播放。
- **120秒**：相比 MP4 直链，HLS 在网络波动下更稳，并为多码率扩展留出接口。当前结论基于本地仿真，真实 CDN 效果还需复测。

### 6) Prisma + PostgreSQL

- **20秒**：PostgreSQL 管关系数据，Prisma 让数据访问有类型约束，减少手写 SQL 失误。
- **60秒**：用户、视频、任务、资源、互动、统计实体关系清晰，事务和约束确保状态更新一致。
- **120秒**：复杂链路下用 schema 统一建模，再通过 `prisma.$transaction()` 保证关键状态同步更新，工程维护成本更低。

### 7) Better Auth

- **20秒**：认证用现成成熟方案，避免重复造登录轮子。
- **60秒**：系统支持邮箱密码和第三方 OAuth，写操作统一通过会话校验。
- **120秒**：鉴权被收敛到统一入口，业务模块不重复写权限逻辑；边界是企业级 SSO 与更复杂策略不在本阶段范围。

### 8) LocalStack

- **20秒**：它是本地 AWS 仿真环境，用于开发联调和流程验证。
- **60秒**：可本地模拟 S3、Lambda、SFN、EventBridge，保证演示和开发可复现。
- **120秒**：它验证的是流程可行性，不等于真实云的权限、网络、配额和成本结论，所以论文结论必须保守描述。

### 9) 触发器与日级汇总

- **20秒**：高频计数在数据库层自动维护，统计用日级汇总减轻在线查询压力。
- **60秒**：点赞评论订阅走触发器，播放事件走异步汇总表，兼顾准确性与性能。
- **120秒**：在线接口只做轻计算，重聚合后移，能降低高并发下响应波动；边界是实时性与复杂报表深度仍可继续优化。

### 10) 测试边界表达

- **20秒**：我证明的是“当前环境下可行”，不是“所有场景都生产可用”。
- **60秒**：功能、异常、并发三类测试覆盖了核心风险，但真实云和更长时段压测还未完整覆盖。
- **120秒**：主动给出边界是工程诚信，不是短板暴露。你先定义结论边界，老师反而更难“追着打”。

## 第五部分：高风险追问反制

### 1) 一致性追问（最常见）

- 老师可能问：你怎么证明状态不会乱？
- 反制答法：主状态与任务状态事务同步更新，失败分支统一回写，stale 机制兜底纠错。
- 证据句：`prisma.$transaction()` + `mark-failed` + `reconcile-stale`。

### 2) 性能追问（容易被压）

- 老师可能问：P99 高了还说可用？
- 反制答法：可用性与性能是不同维度，0 错误率说明可用，P99 上升说明可优化。
- 证据句：测试三指标联合解读，不单看平均值。

### 3) LocalStack 有效性追问

- 老师可能问：仿真环境结果算不算数？
- 反制答法：它证明流程可行与可复现，不直接替代真实云结论；因此论文主动设置边界。
- 证据句：配置封装可迁移，结论已保守表述。

### 4) 传统架构对比追问

- 老师可能问：为什么不用固定服务器集群？
- 反制答法：本项目场景任务波动明显，Serverless 更合适按需触发并降低常驻运维成本。
- 证据句：状态机分段治理比单体长任务更可维护。

### 5) “你是不是只会用框架”追问

- 老师可能问：你只是把库拼起来吗？
- 反制答法：核心价值在系统整合与异常治理，不是“会调 API”，而是“链路可运行且可恢复”。
- 证据句：上传授权、状态机编排、状态回写、统计口径都有明确工程决策。

## 第八部分：附录

### A. 术语白话词典（首次出现先这样讲）

- `Serverless`：服务器仍存在，但运维和弹性由云平台托管。
- `S3`：对象存储仓库，专门放视频这类大文件。
- `Lambda`：按事件触发的小函数工位。
- `Step Functions`：负责多工位顺序、重试和失败分支的流程控制器。
- `EventBridge`：系统事件广播总线。
- `HLS`：把大视频拆成清单和小片段的播放方式。
- `Presigned URL`：后端发临时通行证，让客户端直传文件。
- `Prisma`：把数据库表映射为类型安全的代码访问层。
- `LocalStack`：本地 AWS 仿真环境。
- `P99`：99% 请求都快于该时延，反映尾部卡顿风险。
